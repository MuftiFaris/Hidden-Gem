Live interview assistant
========================

1. Open Zoom, Discord, Meet, a shared document, or the code/problem window.
2. Run release/HiddenGem.exe. Save your Gemini API key in Settings.
3. In Interview Assistant, refresh sources and select the question window.
4. Select the speaker/headphone output used by the call.
5. Press Start Live Assistant. Auto-response is enabled initially.
6. Keep the selected window visible and uncovered, including on a second monitor.
7. New visual tasks or spoken follow-ups populate the question, answer, and history.
8. Turn off auto-response to pause analysis. Press Stop to end capture.

Behavior
--------
- Captures only the selected window's visible rectangle for the live workflow.
- Uses window images internally; there is no manual Screenshot step.
- Screen changes and completed speaker utterances trigger analysis.
- Pauses of 1.2 seconds end an utterance; long speech is processed in 15-second segments.
- Reads screen and transcript together. No regex question rules are required.
- Unchanged screens skip analysis; repeated questions are suppressed.
- API analyses are spaced by at least 8 seconds after completion.
- Speaker capture hears the selected output mix, including unrelated apps if they play on that output.
- Screen questions continue to work when speaker capture is unavailable.
- Images and audio go to Gemini; live behavior depends on the key, quota, connection, and model.
- Closing/minimizing the question window prevents screen reading; the app reports the error and retries.

Verification
------------
Run:
dotnet run --project Assistant.Tests/Assistant.Tests.csproj -c Release -p:Platform=x64 -p:MSBuildEnableWorkloadResolver=false

Checks cover audio requests, WAV metadata, native stereo decoding, model fallback,
streaming, error messages, cancellation, screen-only questions, combined context,
follow-ups, duplicate suppression, screen changes, pause, and stop during API requests.
The tests use simulated responses; they do not prove live Zoom/Discord recognition.
